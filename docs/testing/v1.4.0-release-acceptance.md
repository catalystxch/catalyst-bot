### 2026-09-12 SBX reciprocal-sort defect and live source correction

A cross-market review of all 541 CAT/XCH tickers exposed a reproducible
pagination defect in both standalone Smart Settings and running Market Intel.
Dexie reports buy-direction prices as CAT per XCH. CATalyst requested
`sort=price_desc` and then converted each row to XCH per CAT, so the requested
page contained the worst rather than best bids. DBX had only 53 active bids and
therefore happened to return its complete book. SBX had 964 active bids while
Dexie capped the response at 100; CATalyst consequently saw only the worst 100
and reported a false best bid near `0.00000128` XCH.

The same live endpoint with the correct reciprocal `sort=price_asc` returned an
SBX best bid of `0.000377082959130869...` XCH against best ask `0.000389096`
XCH, approximately a 3.1% spread. A production-path read-only probe after the
fix saw 100 best-page bids, 79 asks, and derived GREEN Balanced confidence for
a 1 XCH configured offer, with 200 XCH bid depth and 209.46973 XCH ask depth
inside the confidence envelope. No wallet or offer mutation was performed.

Focused boundary regressions first failed twice on the emitted `price_desc`
parameter, then passed after changing only the two buy-side queries to
`price_asc`. The complete Smart Settings, Market Intel, market-runtime, and
market-confidence slice passed 164 tests, and Ruff plus `git diff --check`
passed. This correction retains every existing confidence and fail-closed
threshold; it fixes the evidence selection rather than weakening policy.

### 2026-09-12 zero-offer startup fresh-reset conflict

The live browser showed repeated HTTP 409 responses from
`POST /api/session/fresh-start` during ordinary page loading. The read-only
`/api/check-resume` response correctly proved that Sage had zero live offers,
but the no-resume frontend branch then requested a full authoritative reset
without any user action. Durable fill history caused the database safety guard
to reject that reset with `authoritative_state_conflict`; the guard was correct,
but the unsolicited reset request and visible conflict were a frontend defect.

A focused regression first failed against the no-resume branch. The branch now
updates only local presentation state and reserves the guarded reset endpoint
for the explicit Start Fresh control. The frontend, startup-flow, shutdown/
resume, and session-endpoint regression slice passed 100 tests. A live browser
reload then emitted `GET /api/check-resume` with HTTP 200, no fresh-start POST,
and zero console errors or warnings. No wallet, offer, or database mutation was
performed during the live verification.
